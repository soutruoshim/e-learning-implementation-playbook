# Full GitLab CI/CD + Docker + Helm + Kubernetes Setup Guide

This guide follows the architecture from the uploaded PDF and completes the Helm/deployment portion that the transcript cuts off.

The PDF uses three GitLab repositories:

```text
GitLab group: myteam

1. myteam/k8s-connection
   → GitLab Kubernetes Agent

2. myteam/sample-web
   → HTML application
   → Dockerfile
   → Build Docker image
   → GitLab Container Registry

3. myteam/sample-web-helm
   → Helm chart
   → Deploy image to Kubernetes

Kubernetes Agent: prod-agent
Kubernetes namespace: sample-web
Helm release: sample-web
```

The final flow is:

```text
Developer
   │
   │ git push
   ▼
sample-web GitLab repository
   │
   ▼
GitLab CI
   │
   ├── docker build
   └── docker push
          │
          ▼
GitLab Container Registry
          │
          ▼
Trigger Helm repository pipeline
          │
          ▼
sample-web-helm
          │
          │ helm upgrade --install
          ▼
GitLab Kubernetes Agent
          │
          ▼
Kubernetes
   │
   ├── Deployment
   ├── Pods
   └── Service
```

## 6. Test GitLab → Kubernetes Access

In `sample-web-helm`, create a temporary `.gitlab-ci.yml`:

```yaml
stages:
  - test

test-kubernetes:
  stage: test

  image: debian:13-slim

  variables:
    KUBECTL_VERSION: "v1.34"
    DEBIAN_FRONTEND: noninteractive

  before_script:
    - apt-get update
    - apt-get install -y curl ca-certificates gnupg apt-transport-https
    - mkdir -p /etc/apt/keyrings
    - curl -fsSL "https://pkgs.k8s.io/core:/stable:/${KUBECTL_VERSION}/deb/Release.key" |
      gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
    - echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/${KUBECTL_VERSION}/deb/ /" >
      /etc/apt/sources.list.d/kubernetes.list
    - apt-get update
    - apt-get install -y kubectl

  script:
    - kubectl config get-contexts
    - kubectl config use-context myteam/k8s-connection:prod-agent
    - kubectl get nodes
    - kubectl get pods -A
```


## 11. Application `.gitlab-ci.yml`

Create:

```text
sample-web/.gitlab-ci.yml
```

```yaml
stages:
  - build
  - deploy

variables:
  DOCKER_HOST: tcp://docker:2376
  DOCKER_TLS_CERTDIR: "/certs"

build-image:
  stage: build

  image: docker:27.4.1-cli

  services:
    - name: docker:27.4.1-dind
      alias: docker

  before_script:
    - echo "$CI_REGISTRY_PASSWORD" |
      docker login "$CI_REGISTRY"
      --username "$CI_REGISTRY_USER"
      --password-stdin

  script:
    - docker build
      --pull
      -t "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHA"
      .

    - docker push "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHA"

    - |
      if [ "$CI_COMMIT_BRANCH" = "$CI_DEFAULT_BRANCH" ]; then
        docker tag \
          "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHA" \
          "$CI_REGISTRY_IMAGE:latest"

        docker push "$CI_REGISTRY_IMAGE:latest"
      fi

  rules:
    - if: '$CI_COMMIT_BRANCH'
```

> Docker-in-Docker normally requires a GitLab Runner configured with privileged support.

## 19. `deployment.yaml`

Create:

```text
sample-web/templates/deployment.yaml
```

```yaml
apiVersion: apps/v1

kind: Deployment

metadata:
  name: {{ .Release.Name }}

  labels:
    app.kubernetes.io/name: {{ .Chart.Name }}
    app.kubernetes.io/instance: {{ .Release.Name }}

spec:

  replicas: {{ .Values.replicaCount }}

  selector:
    matchLabels:
      app.kubernetes.io/name: {{ .Chart.Name }}
      app.kubernetes.io/instance: {{ .Release.Name }}

  template:

    metadata:

      labels:
        app.kubernetes.io/name: {{ .Chart.Name }}
        app.kubernetes.io/instance: {{ .Release.Name }}

    spec:

      imagePullSecrets:
        {{- toYaml .Values.imagePullSecrets | nindent 8 }}

      containers:

        - name: {{ .Chart.Name }}

          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"

          imagePullPolicy: {{ .Values.image.pullPolicy }}

          ports:

            - name: http
              containerPort: 80
              protocol: TCP

          readinessProbe:

            httpGet:
              path: /
              port: http

            initialDelaySeconds: 3
            periodSeconds: 5

          livenessProbe:

            httpGet:
              path: /
              port: http

            initialDelaySeconds: 10
            periodSeconds: 10

          resources:

            {{- toYaml .Values.resources | nindent 12 }}
```

# 24. Automate Helm Deployment

Create:

```text
sample-web-helm/.gitlab-ci.yml
```

```yaml
spec:

  inputs:

    image_repository:

      description: "Docker image repository"

      default: "registry.gitlab.com/myteam/sample-web"

    image_tag:

      description: "Docker image tag"

      default: "latest"

---

stages:

  - validate

  - deploy


variables:

  AGENT_KUBECONTEXT: "myteam/k8s-connection:prod-agent"

  KUBE_NAMESPACE: "sample-web"

  RELEASE_NAME: "sample-web"


validate-helm:

  stage: validate

  image:
    name: alpine/helm:4.3.0
    entrypoint: [""]

  script:

    - helm lint ./sample-web

    - helm template
      "$RELEASE_NAME"
      ./sample-web
      --set-string image.repository="$[[ inputs.image_repository ]]"
      --set-string image.tag="$[[ inputs.image_tag ]]"


deploy-production:

  stage: deploy

  image:
    name: alpine/helm:4.3.0
    entrypoint: [""]

  script:

    - helm upgrade
      --install
      "$RELEASE_NAME"
      ./sample-web
      --namespace "$KUBE_NAMESPACE"
      --create-namespace
      --kube-context "$AGENT_KUBECONTEXT"
      --set-string image.repository="$[[ inputs.image_repository ]]"
      --set-string image.tag="$[[ inputs.image_tag ]]"
      --wait
      --atomic
      --timeout 5m

  environment:

    name: production

  rules:

    - if: '$CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH'
```

# 31. What Helm Actually Does

Helm does not run the application itself.

Helm renders and manages Kubernetes resources.

```text
Helm
 │
 │ renders templates
 ▼
Deployment
 │
 ▼
ReplicaSet
 │
 ▼
Pods
```

And:

```text
Service
 │
 ▼
Pods
```

Think of it as:

```text
Helm = package/template/deployment manager

Kubernetes = actually runs your application
```

# 36. Troubleshooting

## `ImagePullBackOff`

Run:

```bash
kubectl describe pod <pod-name> -n sample-web
```

Check:

```bash
kubectl get secret gitlab-registry-auth -n sample-web
```

Usually this means Kubernetes cannot authenticate with the GitLab Container Registry.

---

## `no context exists`

Inside CI:

```bash
kubectl config get-contexts
```

Expected context:

```text
myteam/k8s-connection:prod-agent
```

Check:

```yaml
ci_access:
  projects:
    - id: myteam/sample-web-helm
```

And confirm the file is:

```text
.gitlab/agents/prod-agent/config.yaml
```

---

## Docker Cannot Connect to Daemon

Error:

```text
Cannot connect to the Docker daemon
```

Check your GitLab Runner.

Docker-in-Docker commonly requires:

```toml
[runners.docker]

privileged = true
```

---

## Helm Returns `Forbidden`

Example:

```text
deployments.apps is forbidden
```

This means the GitLab Agent's Kubernetes identity does not have enough RBAC permissions.

For production, use restricted RBAC rather than giving broad cluster-admin permissions.
